# Go backend

## Layout

- `internal/store` is the only SQL boundary. Keep queries, transactions, scanning, and migrations here.
- `internal/api` handles HTTP: routing, middleware, request parsing, status codes, response shapes.
- `internal/auth` owns password verification, token generation/hashing, and cookie flags.
- `internal/config` owns environment parsing and validation.
- `main.go` wires dependencies and owns startup/shutdown.

## Conventions

- Pass `context.Context` as the first parameter to store and external calls.
- Wrap errors with context: `fmt.Errorf("action: %w", err)`.
- Return `store.ErrNotFound` for missing rows and validation errors that unwrap to `store.ErrValidation`; user-facing messages go in `ValidationError`.
- Use `respondError` and `handleStoreError` in handlers; do not invent new error shapes.
- Keep JSON camelCase to match `web/src/api/types.ts`. Success payloads are objects such as `{"tasks": [...]}`; errors use `{"error": {"code": "...", "message": "..."}}`.
- Store timestamps in UTC via `internal/store/timeutil.go`; never hand-format them in handlers.
- SQLite runs with one connection, WAL, foreign keys, and a busy timeout. Do not add a connection pool or a second database.
- Schema changes require a new numbered migration: `internal/store/migrations/NNN_description.sql`. The runner applies each file in a transaction and records `PRAGMA user_version`.
- Enforce invariants in SQL where practical (`CHECK` constraints) and in Go validation for user messages.
- Keep handlers thin. Business rules belong in `store` or `auth`, not in Gin callbacks.

## Skills: load when the change matches

| Change | Skill |
| --- | --- |
| Nil pointers, typed-nil interfaces, slice aliasing, numeric truncation, float equality, `defer` in loops, defensive copies, zero values | `golang-safety` |
| Goroutines, channels, `select`, mutexes, atomics, tickers, worker pools, cancellation, graceful shutdown, login limiter, session cleanup | `golang-concurrency` |
| A measured hot path (pprof/benchmark shows the bottleneck) | `golang-performance` |
| Writing or comparing benchmarks, pprof methodology, benchstat | `golang-benchmark` |
| A crash, race, deadlock, hang, or unexpected behavior | `golang-troubleshooting` |

Load the skill before editing when the change clearly matches; otherwise implement normally and load it if the problem turns out to be in that area.

## Tests

- Add table-driven tests for validation and edge cases.
- Cover success, validation, not-found, and internal error paths for new handlers.
- Use `-tags dev` so tests do not need `web/dist`:
  `go test -tags dev ./...`
- Prefer `t.TempDir()` or an in-memory SQLite database; never write to the repo `data/` directory from tests.
- Run `gofmt -w` and `go vet -tags dev ./...` before finishing.

## Security

- Never log passwords, raw session tokens, or cookie values.
- Session tokens are random and only their SHA-256 hash is stored.
- Keep cookies `HttpOnly`, `SameSite=Strict`, and `Secure` when configured.
- Keep the 64 KiB request-body cap, CSRF-relevant cookie behavior, and security headers intact.
- Validate and bound all user input; do not add endpoints that bypass `requireAuth` unless they are explicitly public.
- Do not raise login limits, session TTL, or body limits without explicit approval.
